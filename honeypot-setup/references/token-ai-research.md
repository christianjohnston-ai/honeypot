## Mechanisms that must not be conflated

- [HTTP token](https://docs.canarytokens.org/guide/http-token): URL request, not reading a text file containing it. In a managed application, a private decoy document can contain that URL; this detects following it, not all database access. Serving a URL in public HTML may cause browser/prefetch/preview noise.
- [DNS token](https://docs.canarytokens.org/guide/dns-token): resolving the unique name, not merely viewing it. Recursive resolver/caching can hide the original client or suppress repeated lookups.
- [PDF](https://docs.canarytokens.org/guide/adobe-pdf-token): a compatible reader makes a DNS lookup. Raw reads or readers without the callback are not covered; reported address may identify the resolver. [Word](https://docs.canarytokens.org/guide/ms-word-token): upstream documents Microsoft Office on Windows/macOS; verify actual application/network behavior, including blocked external content, rather than assuming every viewer fires.
- [AWS keys](https://docs.canarytokens.org/guide/aws-keys-token): provider-issued defanged key pair must be used against AWS. Merely copying the file does not fire. Upstream reports typical 2–30 minute logging delay. A [separate commercial support explanation](https://help.canary.tools/hc/en-gb/articles/4415516925585-AWS-API-Key-Canarytoken-safety-net-triggered) documents AWS logging gaps and safety-net checks; do not infer instant or exhaustive alerts for the public service. Do not attach privileges, replace a real default profile, or put the pair into active production authentication. Follow the issuing service's current terms and place only in private authorized locations.
- [MCP configuration](https://docs.canarytokens.org/guide/mcp-token): explicitly select connection versus tool-call trigger. JSON file access is not monitored. Test in an empty client profile; never merge a decoy over existing production connections.
- Locally monitored decoy file: content change/removal can be observed by an integrity monitor. Opening/reading requires OS auditing or a document callback. File changes can be legitimate and do not identify ransomware or its process by themselves.

## Deprecations and delivery limits

New **Slack API Canarytokens are deprecated**, as stated in the pinned [README](https://github.com/thinkst/canarytokens/blob/61f3e0c7790f08f1be09a947cb0d68e6152cde6a/README.md#deprecations). This does **not** deprecate Slack incoming webhooks as an alert destination. Old tokens may continue to function; verify each individually.

Inspected [webhook sender](https://github.com/thinkst/canarytokens/blob/61f3e0c7790f08f1be09a947cb0d68e6152cde6a/canarytokens/channel_output_webhook.py) sends one request with `(2,2)` connection/read timeout and no retry loop. Failed deliveries increment a counter; README says disable after five consecutive errors, while this revision's conditional is `alert_failure_count > MAX_ALERT_FAILURES` with default 5. Do not depend on the off-by-one behavior; check the actual token's enabled state after repeated failures. Default upstream throttling is one alert per unique calling IP per minute; history may still contain suppressed events. Hosted service settings may differ.

Generic payload has `channel`, `token_type`, `src_ip`, `src_data`, `token`, `time`, `memo`, `manage_url`, `additional_data`, `public_domain` ([model](https://github.com/thinkst/canarytokens/blob/61f3e0c7790f08f1be09a947cb0d68e6152cde6a/canarytokens/models/common.py)). `time` serializes as `YYYY-MM-DD HH:MM:SS (UTC)`. No guaranteed event ID. Native payloads include sensitive capability URLs and attacker-controlled strings; forward only an allowlist. Provider-generated webhook-validation messages are not controlled decoy interactions.

## Research-to-implementation boundary

This package recommends hosted private-email tokens for low-ops users, and a hosted MCP token for configuration-use detection. Beelzebub and self-hosted Canarytokens remain advanced alternatives requiring live environment validation and additional alert integration. Their configuration/source was reviewed, not deployed. Never claim either is accepted until the three runtime acceptance checks pass.
