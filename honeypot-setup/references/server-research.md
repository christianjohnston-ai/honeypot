# Server honeypot research

Access date: **2026-11-23**. “Documented” below means upstream documentation/source inspection, not deployed behavior. “Inference” identifies our routing judgment. No popularity metric is used as reliability evidence. Raw metadata was obtained from the public GitHub repositories, release and security-advisory APIs; public advisory absence does not establish that software or its dependencies are vulnerability-free. Recheck release/advisory state before installation.

## OpenCanary: exact source findings

Reviewed default-branch commit **`ece4a855587de1127d76b0d6188916908361b7cd`**, committed 2026-11-23. Latest observed release **v0.9.10**, published 2026-09-21; the release tag resolves to **`fb12e4fefbdb1b9acd1e5561a2614f827ab639ff`**, used for the packaged route. Previous v0.9.9 (2026-07-22) and v0.9.8 (2026-05-18) show ongoing release activity. [Release history](https://github.com/thinkst/opencanary/releases), [tagged source](https://github.com/thinkst/opencanary/tree/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff).

The source logger assigns `node_id`, `utc_time`, `local_time`, `local_time_adjusted`, source/destination host/port, numeric `logtype`, and `logdata`. `utc_time` lacks a zone suffix but is generated using UTC; `local_time` is also populated from UTC despite its name. No native per-event UUID is assigned here. The helper derives a stable correlation ID from the event. Logdata can include plaintext attempted passwords; do not forward it to ordinary notifications or treat it as instructions. [Logger source](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/opencanary/logger.py).

| Interaction | Event code and boundary |
|---|---|
| FTP USER/PASS attempt | `2000`; mere TCP connect is insufficient. Optional “auth initiated” is `2001`. |
| HTTP GET `/index.html` | `3000`; GET `/` is redirect `3003` only when enabled. Login POST `3001`; unsupported methods `3002` only when enabled. Static requests are not blanket access detection. |
| SSH connection / version / auth | `4000` / `4001` / `4002`. |
| Audited Samba share event | `5000`; not local file read monitoring. |
| SYN portscan event | `5001`; Linux iptables-only module, disabled under Docker. |
| Telnet login | `6001`. |
| HTTP proxy login | `7001`. |
| MySQL login | `8001`. |
| RDP interaction | `14001`. |

These codes differ substantially from mappings in the examined community skills. Validate a new protocol against its own module, not a copied lookup table. [FTP module](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/opencanary/modules/ftp.py), [HTTP module](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/opencanary/modules/http.py).

Docker startup reads trusted config before dropping privileges; its logging configuration can instantiate Python objects. Root ownership and a read-only mount are meaningful safeguards. The pinned startup file creates the logger before Twisted sheds privileges. Because this template removes DAC_OVERRIDE, its dedicated log directory is nobody:root with setgid mode 2770 and startup umask 0007: both initial root and later nobody can write, including after rotation/restart. `/run` permits the same two identities for PID lifecycle. These permission choices are source-reviewed, not container-executed. [Startup source](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/bin/opencanary.tac), [locked Twisted startup](https://github.com/twisted/twisted/blob/twisted-26.4.0/src/twisted/scripts/_twistd_unix.py). Upstream `Dockerfile.stable` installs an unversioned package; `Dockerfile.latest` builds checked-out source with `uv sync --frozen`. The package pins a reviewed release source, and honestly leaves base/apt dependency resolution as a recorded build-time variable. Host networking ignores published-port mappings, so our template omits `ports` and uses the configured bind address plus host/provider firewall. [Configuration implementation](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/opencanary/config.py), [Dockerfile](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/Dockerfile.latest), [Docker host driver](https://docs.docker.com/engine/network/drivers/host/).

Native SMTP is documented, but upstream examples include old Python2 links, port25 and example credentials; do not copy them as a universally working mail setup. Use the actual user's provider-supported authenticated TLS route. Native generic webhook forwards a formatted full message by default, with optional Requests arguments; Slack and Teams handlers forward broad event fields. These handlers do not implement a durable outbox. A valid webhook HTTP status proves endpoint acceptance only. [SMTP docs](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/docs/alerts/email.rst), [Webhook docs](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/docs/alerts/webhook.md).

Samba support tails an audit log; the setting is `smb.auditfile`, not `smb.filelist`. The upstream wiki's tested combination is Samba 4.15.13/Ubuntu 22.04 with rsyslog and a particular full_audit format. Verify the installed Samba audit operation names and perform a real harmless open before claiming detection; backups/indexers may legitimately access decoys. This is an optional extension, not the packaged HTTP route. [Samba source](https://github.com/thinkst/opencanary/blob/fb12e4fefbdb1b9acd1e5561a2614f827ab639ff/opencanary/modules/samba.py), [Samba guide](https://github.com/thinkst/opencanary/wiki/Opencanary-and-Samba).

Published advisories checked:

- [CVE-2026-85219 / Redis DoS](https://github.com/thinkst/opencanary/security/advisories/GHSA-77jg-5rmj-77jx): patched v0.9.10; disabling Redis is a documented workaround.
- [CVE-2026-16551 / MongoDB DoS](https://github.com/thinkst/opencanary/security/advisories/GHSA-vg37-pc42-q265): patched v0.9.9.
- [CVE-2024-48911 / writable config command execution](https://github.com/thinkst/opencanary/security/advisories/GHSA-pf5v-pqfv-x8jj): prose says upgrade 0.9.4+, structured affected range says `<0.9.5`; this package uses 0.9.10+ and root-controlled config, not the ambiguous boundary.
- [MySQL fingerprinting advisory](https://github.com/thinkst/opencanary/security/advisories/GHSA-qchx-hrfc-32wg): fixed 0.6.1; illustrates that decoys can be identified rather than guaranteeing deception.

## Cowrie: maintenance, containment and alert caveats

Observed main **`183a3b1bc361bb941e1d54874922399baac42af0`** (2026-11-23). GitHub latest release **v3.1.8**, published 2026-11-23; previous v3.1.7 Nov16 and v3.1.6 Nov9. The inspected `CHANGELOG.rst` had release 3.1.5 and an Unreleased section while the documentation rendered a development version string; do not conflate HEAD/docs/release version. For a deployment choose a release, inspect its bundled configuration and pinned dependencies, then test that version. [Releases](https://github.com/cowrie/cowrie/releases), [source at observed commit](https://github.com/cowrie/cowrie/tree/183a3b1bc361bb941e1d54874922399baac42af0), [installation](https://docs.cowrie.org/en/latest/INSTALL.html).

`cowrie init` refuses to overwrite existing config rather than being an idempotent reset. Run only for a new state directory. Cowrie's structured events include UTC timestamp, session ID, event type, sensor and source IP, enabling correlation. Captured commands/downloads are hostile evidence: don't execute or ask an agent to follow them. [Event reference](https://docs.cowrie.org/en/latest/OUTPUT.html), [bundled defaults](https://github.com/cowrie/cowrie/blob/183a3b1bc361bb941e1d54874922399baac42af0/src/cowrie/data/etc/cowrie.cfg.dist).

Slack output uses a bot token/channel. Telegram sends selected login-success, command and download events; Discord has delay/retry settings. Exact payload selection and current channel API compatibility require runtime validation. Do not claim every connection produces every channel alert or label installed plugins as tested. Database/SIEM destinations offer additional integration paths; native email was not established in inspected defaults.

[GHSA-83jg-m2pm-4jxj](https://github.com/cowrie/cowrie/security/advisories/GHSA-83jg-m2pm-4jxj) describes emulated wget/curl making actual outbound HTTP requests and abuse as an amplification source, observed in the wild; patched 2.9.0 adds rate limits. Current versions still warrant strict outbound controls, especially blocking production/metadata access. Latest source changelog also contains unreleased resource-exhaustion hardening; reviewed source is not a substitute for dependency scanning and containment.

License: [BSD-3-Clause main license](https://github.com/cowrie/cowrie/blob/183a3b1bc361bb941e1d54874922399baac42af0/LICENSE.rst), plus per-file `LICENSES`/REUSE metadata. GitHub's repository license API returned `NOASSERTION`, so we inspected the license text rather than treating API metadata as proof of no license. Preserve required notices for any reused material.

## T-Pot: scope and private telemetry

Observed HEAD **`9c3ae4aea976a63ef1f655598a4383c0cb7e140c`**, committed 2026-11-19. Latest GitHub release **24.04.1**, published 2024-12-11; ongoing commits/images and current README demonstrate maintenance beyond the release tag. Release images are updated continuously; a tag does not fix every component's bytes. A pin/update inventory must include Compose, each image digest and persistent-data migrations. [Releases](https://github.com/telekom-security/tpotce/releases), [current README at observed commit](https://github.com/telekom-security/tpotce/blob/9c3ae4aea976a63ef1f655598a4383c0cb7e140c/README.md).

The current supported-distribution table includes Alma/Rocky 10, Debian 13, Fedora 44, openSUSE Tumbleweed, Ubuntu 26.04, and RHEL 10 notes; older release notes name different distributions. Read the table for the selected checkout before installation. Installer convenience commands download and execute shell code; our skill does not execute those blindly. The installer can change SSH and other services, so use a dedicated system and review the script/Ansible tasks first. A public internet research deployment with many ports is a separate authorized undertaking.

Logs/artifacts persist under the deployment data directory; Elasticsearch retention is governed separately by index lifecycle policy. A dashboard screenshot or healthy container is not proof of email delivery. Review destination connector licensing at runtime before promising email, Slack or webhook delivery. The default community submission is a real data-sharing difference even though this is “self-hosted.” [Compose](https://github.com/telekom-security/tpotce/blob/9c3ae4aea976a63ef1f655598a4383c0cb7e140c/docker-compose.yml), [environment example](https://github.com/telekom-security/tpotce/blob/9c3ae4aea976a63ef1f655598a4383c0cb7e140c/env.example).

The [public security-advisory page](https://github.com/telekom-security/tpotce/security/advisories) returned no published advisories during this review. This says nothing about each bundled sensor, Docker/OS dependency or Elastic component. Review component advisories/image scans. [Security policy](https://github.com/telekom-security/tpotce/blob/9c3ae4aea976a63ef1f655598a4383c0cb7e140c/SECURITY.md).

## Evidence limits

Executed in this research: read-only web/API retrieval; local inspection of source/config/docs; JSON and YAML parsing of the newly authored OpenCanary templates; assertions for loopback-only single-protocol configuration, capability restrictions and read-only mounts; `docker compose -f honeypot-setup/templates/opencanary-compose.yaml config --quiet` (passed). `docker version` found the macOS/ARM64 client 27.3.1 but no running daemon, so container execution was unavailable. No upstream installation script was executed. No VM, container honeypot, production network change, real malware interaction, cloud resource or external notification delivery was performed by this research subtask. Resource/cost estimates and recommendation priorities are explicitly engineering inferences. The local adapter's tests are reported separately in the package validation report.
