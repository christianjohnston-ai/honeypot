# Platform fit and preflight

Documentation reviewed **2026-11-23**. These are documented capabilities and engineering inferences, not deployment test results. Verify the selected product, plan, region and current CLI before acting. A provider name alone does not identify its runtime.

## Decision matrix

| Environment | Documented constraints | Route and placement | Additional checks |
|---|---|---|---|
| Vercel Functions / managed frontend | Request execution has duration/resource limits. Current Vercel also offers continuous **Daemons beta**, which pull work over outbound connections and use ephemeral storage. This is not an arbitrary inbound SSH honeypot interface. [Functions limits](https://vercel.com/docs/functions/limitations), [workers](https://vercel.com/docs/background-workers), [Daemons](https://vercel.com/docs/daemons) | Hosted token in a private asset the suspected actor could actually access; or a decoy HTTP handler in the existing application with a durable event sink. | No SSH assumption. Inspect framework/version, route middleware, deployment protection, cache behavior and logging retention. New worker resources are optional, billable design choices. |
| Netlify Functions / static site | Functions are bounded: documented synchronous limit 60 seconds, background 15 minutes. Current **Netlify Server Early Access** runs Node HTTP processes but scales to zero when idle. [Functions configuration](https://docs.netlify.com/build/functions/configuration/), [Server](https://docs.netlify.com/build/server/) | Hosted token; or HTTP function/handler plus durable queue. A static file without a callback or server-side logging rule is not a monitored file. | Inspect publish/functions directories so source and secrets are not public. Server Early Access is not evidence that arbitrary TCP/UDP honeypots are supported. |
| Cloudflare Workers / Pages | Ordinary `fetch` handlers receive HTTP requests. `connect()` supports outbound TCP. Current inbound TCP **public beta** requires a `connect` handler and service binding or Spectrum origin configuration. Workers have CPU/memory limits. [TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/), [limits](https://developers.cloudflare.com/workers/platform/limits/) | HTTP decoy plus Queue; or hosted token. A custom TCP decoy is separate engineering requiring Spectrum/plan verification; OpenCanary is not a drop-in Worker. | Check Worker routes, bindings and secrets. Persist events outside process memory. Do not assume inbound UDP, root access or a writable durable local filesystem. |
| Supabase hosted | Edge Functions are bounded (documented 256 MB memory, wall-clock 150 seconds free / 400 seconds paid). `/tmp` is temporary; persistent file storage is a distinct S3-backed facility. [limits](https://supabase.com/docs/guides/functions/limits), [storage](https://supabase.com/docs/guides/functions/ephemeral-storage) | Hosted token in a private document/config repository; or narrowly scoped app decoy with a private event queue. | An ordinary fake table row does not alert on SELECT. Database webhooks/row-change events are not read detectors. Preserve RLS, API grants and auth. Never place service-role/secret keys in frontend code. |
| Firebase hosting / Functions | Functions are stateless, bounded, and must finish asynchronous work before return; temporary disk is not durable storage. [tips](https://firebase.google.com/docs/functions/tips), [quotas](https://firebase.google.com/docs/functions/quotas) | Hosted token or HTTPS `onRequest` decoy with durable event storage/queue. | Identify Functions generation, plan and existing IAM/auth rules; do not infer host/root access from Firebase console access. A Firestore document read is not an update trigger. |
| Render public web service | Binds to `0.0.0.0` and normally `PORT`; only one public HTTP ingress port. Other ports are available privately. Free web services sleep after 15 idle minutes. Files are ephemeral unless under a paid persistent disk mount. [web services](https://render.com/docs/web-services), [free](https://render.com/docs/free), [disks](https://render.com/docs/disks) | Existing HTTP app decoy, hosted token, or separate paid HTTP decoy service. Do not publish Cowrie SSH as a public Render HTTP service. | Verify actual `PORT`, health path, wake behavior and retention. Do not replace app start command with a honeypot. New service/disk cost needs an estimate and scoped authorization. |
| Render private service | Web/private services can receive nearly any protocol on private ports; free web services and background workers cannot receive private traffic. Same-region workspace networking is shared; environment isolation controls depend on plan. [private network](https://render.com/docs/private-network) | Private decoy only after proving a one-way reachability/isolation design. An app on the same private network may reach the decoy, but the decoy must not gain access back to production. | Check plan-supported network isolation. A separate VM is preferable if required outbound controls cannot be established. |
| Railway container service | Public HTTP/HTTPS and a separate raw TCP Proxy are supported. TCP Proxy assigns a hostname and external port. Volumes persist selected directories. Serverless mode can sleep services and the first wake request can return 502. [TCP Proxy](https://docs.railway.com/networking/tcp-proxy), [volumes](https://docs.railway.com/volumes), [Serverless](https://docs.railway.com/deployments/serverless) | HTTP decoy is the simpler default. A single-protocol TCP decoy is feasible only after validating image, assigned port, source-IP visibility and isolation; do not promise arbitrary UDP or standard external port 22. | Disable sleep for continuous monitoring if supported/authorized; inspect project private networking and outbound controls. A volume is required for a local outbox. Provider proxy IP may replace the original source: verify in a real test. |
| AWS / Azure / GCP / other Linux VM | VM network controls permit protocol/port-specific ingress and egress. Provider firewall semantics differ. [AWS security groups](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html), [Azure NSGs](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview), [GCP VPC firewall](https://docs.cloud.google.com/firewall/docs/firewalls) | Dedicated isolated OpenCanary VM/container; place on the network where the intended suspicious access would reach it. | Verify OS, architecture, Docker/Compose version, admin access, port conflicts, disk space, time sync and management recovery. No production credentials or mounted Docker socket inside decoy. Restrict both cloud and host networking. |
| Local developer machine | Capability depends on OS, process supervision, sleep and local firewall. A portable URL/DNS/credential token needs no local daemon but requires its specific use to contact the service. | Hosted token for credential-use or callback detection. For file changes, an explicitly installed watcher can detect writes/deletion while running. | Reading plain text does not necessarily trigger anything. File watchers differ from document callbacks, DNS resolution and API-key use. A sleeping/offline laptop cannot promise continuous local observation. Windows ACL handling for sensitive local state is implemented and tested, but scheduler and lifecycle behavior remain separately unverified. |
| Shared hosting / dashboard only | No universal process, root, port, cron or outbound-network guarantee. | Hosted token in an accessible private asset, or an existing supported application handler. | If only a static upload is allowed, there may be no feasible server-side request detector. Ask host administrator for supported request logging/alerting or use an isolated external decoy, explaining its limited placement coverage. |

## Verify only what the next action needs

1. Read nonsecret manifests and deployment descriptors (`package.json`, framework config, Dockerfile, `render.yaml`, `railway.json`, `vercel.json`, `netlify.toml`, `wrangler.*`, function directory names). Do not read whole environment/credential files. Summarize the inferred stack for correction.
2. Identify the precise service, project/environment, route, network boundary, owner and deployment identifier. Inspect the existing resource before proposing another one.
3. Use dashboard read access or installed CLI `--help` to verify the current plan, inbound protocol, target port, process lifecycle, storage mount, secrets mechanism, logging retention, costs and permissions. Record the date/source.
4. Prepare a focused diff and rollback. Preserve unrelated settings. A new public listener, paid resource or production change outside existing authorization needs approval of that concrete proposal.
5. Run one harmless test from the actual intended network. A test from inside a container cannot validate the provider ingress path or source attribution.

Docker changes host packet filtering, and published container ports can bypass expected `ufw` handling. Check actual cloud/host rules and validate from an allowed and a disallowed source; do not rely on a single `ufw` rule. [Docker firewall documentation](https://docs.docker.com/engine/network/packet-filtering-firewalls/)

## Durable alert path choices

Use an existing authenticated event queue or alerting service when possible. Cloudflare Queues documents at-least-once delivery; retain an event ID for consumer deduplication. Vercel Queues beta documents durable topics and retries. Supabase Queues is Postgres-backed. These are possible integration building blocks, not preconfigured backends in this package. Read the chosen provider's current API before implementing. [Cloudflare delivery guarantees](https://developers.cloudflare.com/queues/reference/delivery-guarantees/), [Vercel Queues](https://vercel.com/docs/queues), [Supabase Queues](https://supabase.com/docs/guides/queues)

Supabase's current changelog documents CLI v3 local-default/hosted-confirmation changes and scoped permissions for branch merges. Inspect installed CLI help before producing deployment commands; do not copy historical v2 commands blindly. [Changelog](https://supabase.com/changelog.md), [CLI v3 change](https://supabase.com/changelog/supabase-cli-v3)

## Cost assumptions

Hosted token services can avoid a VM but retain their service limits and data-handling terms. Existing HTTP decoys can still incur function invocations, queue operations, logs, storage and notification charges under scanning. A VM adds compute, disk, public IP, egress and patching costs. LLM honeypots add inference costs. Estimate using the user's selected provider/region/plan at runtime; this package makes no fixed-price promise.
